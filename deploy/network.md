# 跨网段故障排查

按症状查，比按原理查快。每一节都给出「最可能的原因」和「怎么确认」。

## 症状一：完全看不到对方

**先确认是不是跨网段。** 同一个网段内自动发现不需要任何配置；跨网段必须有种子。

排查顺序：

1. 对方的状态灯是红的（离线）还是黄的（仅限同网段）？
2. 你这边加了他的种子地址吗？格式是 `IP:端口`，端口**是 UDP 端口**，不是 TCP；
3. 种子那一行的「测试」按钮通过了吗？它会分别报 UDP 与 TCP 两跳；
4. 两台机器能不能 `ping` 通？ping 通只证明 ICMP 通，不代表 TCP 端口可达 —— 别停在这一步。

## 症状二：看得到人，但发不出消息

**这是最典型的一种：UDP 通、TCP 被防火墙挡住。**

发现（把你加到列表里）走 UDP，消息与文件走 TCP。所以「能看到人」和「能聊天」是两件事，各自需要放行。

确认方法：种子的「测试」按钮显示 UDP 通过、TCP 失败；或者用 `telnet <对方IP> <tcp端口>` 看是否连得上。

## 症状三：时好时坏，重启就好一阵

**最可能是地址段冲突（P-2）。** 多个网段都用了 `192.168.1.0/24`，目录里出现 node_id 不同但 IP 相同的条目，寻址会随机命中错的那台。

确认方法：开[调试面板](../guide/peers.md)，看节点列表里有没有 IP 相同、名字不同的条目。有的话，先改地址段 —— 软件层面绕不过去。

## 症状四：共享里看不到对方的文件

- 对方在线吗？共享是实时从对方电脑取的，不在线就看不到，也不会排队；
- 对方把共享的可见范围设成「仅指定的人」或「仅群组」了吗？
- 对方刚发布完吗？列表刷新有短暂延迟，点一下刷新。

## 症状五：换网卡或接 VPN 之后就不对了

发现报文可能从错误的网卡发出去了。去配置里把虚拟网卡加进 `deny_interfaces`（默认已含常见项），然后重启软件。

配置项的含义见[配置与数据目录](../dev/config.md)。

## 一份最短的现场检查清单

- [ ] 各网段地址段不重叠（P-2）
- [ ] 种子之间能 TCP 直连（P-1）
- [ ] 防火墙放行了 **TCP 和 UDP** 两个端口
- [ ] 种子机器固定了 `udp_port`
- [ ] 装完跑过一次部署自检，结果截图存档
