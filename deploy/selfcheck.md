# 部署自检怎么用

入口：设置 → **部署自检** → 运行自检。

它不做假动作：会真实探通每个种子、真实拉取一次目录，然后给出结论。所以它跑得比一般「检查网络」慢一点，但结论可信。

![部署自检：逐项检查后直接指出问题所在](../screenshots/09-settings-selfcheck.png)

## 它会检查什么

| 检查项 | 通过意味着 | 失败通常意味着 |
|---|---|---|
| 本机监听 | 端口已占用并正常监听 | 端口被别的程序占了，或没有权限 |
| 本机发现 | 本地广播能发出去 | 网卡选择错误，或防火墙拦了 UDP |
| 种子连通（UDP） | 种子能收到你的询问并回话 | 种子地址错、种子没固定端口、UDP 被挡 |
| 种子连通（TCP） | 能真的连上种子的 TCP 端口 | 防火墙只放了 UDP，没放 TCP |
| 目录拉取 | 能取到跨网段节点列表 | 路由不通，或对端认证失败 |

## 结果怎么读

**先看第一个失败的项，不用管后面的。** 后面的失败多半是被第一项拖下来的：TCP 不通，目录自然拉不到。

**UDP 过、TCP 不过** 是最常见的一种，几乎都是防火墙只放行了 UDP。去把 TCP 端口也放行，不用重装软件。

**全部通过，但联系人列表还是空的**，那问题不在网络层：看对方是否在线、是否在同一个群组可见范围内，或者开[调试面板](../guide/peers.md)看节点数。

## 建议的用法

1. **装完立刻跑一次**，拿到一份「基线结论」；
2. 现场网络动过之后（换交换机、加防火墙规则、改 VPN）再跑一次，对比哪一项变了；
3. 交付前把结果截图存档 —— 客户说「连不上」时，这张图能省掉很多争论。
