# 部署前必读

这一页给负责把蜂群装进现场的人：IT 管理员、系统集成方，或者要评估能不能用的技术负责人。

**部署前先在现场机器上跑一次自检**：设置 →「部署自检」→ 运行自检。它会真实探通每个种子、拉取目录，并给出 P-1 / P-2 的结论 —— 比事后排查便宜得多。

## 两个硬条件

| 编号 | 前置条件 | 不满足的后果 |
|---|---|---|
| **P-1** | 任意两网段的种子 IP 之间**可 TCP 直连**（三层路由可达，非 NAT 隔离） | 跨网段发现与消息**全部失效** |
| **P-2** | 各网段使用**不重叠的地址段**（不得都是 `192.168.1.0/24`） | 目录中出现 node_id 不同、IP 相同的条目，跨网段寻址崩溃且**极难排查** |

::: warning P-2 不是理论风险
「多个厂区各用一个 `192.168.1.0/24`，再靠 VPN 互联」是内网最常见的形态之一。这种情况下自动发现会在地址上撞车 —— 表现是有时候能看到人、有时候看不到，重启就好一阵，然后复发。
:::

## 另外两项现场必做

**防火墙放行 TCP/UDP 端口。** 默认端口写在配置里，见[配置与数据目录](../dev/config.md)。跨网段时最常见的故障就是「UDP 通、TCP 被挡」：能看到人，发不出消息。

**种子机器固定 `udp_port`。** 关闭端口自动回退，否则跨网段节点拿着配置里的端口发第一个报文就石沉大海。`tcp_port` 仍可回退 —— 对端会从种子回传的通告里学到实际端口。

**VPN 场景把虚拟网卡加入 `deny_interfaces`。** 默认已包含常见项；如果你的 VPN 网卡名字特殊，需要自己加，否则发现报文会从错误的网卡发出去。

## 它做不到什么

**两个网段之间被防火墙或 NAT 彻底隔开，软件帮不上忙。** 蜂群刻意不做中继服务器：加了中继，数据就真的经过中间机器，「不出内网」也就不成立了。

遇到这种情况，只有三条路：打通网络、加一台跳板机自己做转发、或者放弃跨网段只在本段内用。
